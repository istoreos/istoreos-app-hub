# Kai 桌面入口退出

按用户决策，桌面入口由 KaiPlus 承接；经典版 Kai 不注册新目录或旧目录入口。

- Kai 新装不再安装桌面清单、图标或注册链接，移除仅为共享应用入口增加的依赖；保留原有服务、配置、会话运行时与认证依赖。
- Kai 的 postinst/prerm 精确清理新旧目录中仍指向自身旧清单的 05-kai-plugin.json，保留自定义普通文件、目录和其他链接，KaiPlus 入口不变。
- KaiPlus 的经典版安装检测改为检查实际运行文件，不再依赖桌面清单。状态返回有效服务端口，打开按钮经现有 LuCI 认证桥转到当前设备的 http://设备:端口/apps/kai/；支持自定义端口和 IPv6，非法端口不生成链接。认证桥代码和校验规则不变。
- Kai 发布号 12 → 13，luci-app-kaiplus 1.0.11-r1 → r2，产品元包发布号 5 → 6。按映射同步 openwrt-app-actions、openwrt-app-meta；显式删除旧桌面资源。

验收：Kai 退出测试 3 项、其余 8 应用注册测试 9 项、经典版交互测试 6 项、元包归属测试 1 项通过。经典版 Lua 测试在 .7、.164 的解释器分别执行，均使用 I/O 桩；浏览器行为由现有 Node VM 测试验证。未部署业务服务，也未进行实际浏览器/设备服务端到端验收。

既有失败：test-local-agent-contract.sh 在修改前 HEAD 的隔离副本上同样因缺少技能包最低版本约束失败；本轮只更新其与启动入口有关的检查，不修改无关版本依赖。该套完整测试不计入通过项，详见 [基线复现](existing-test-failure.json)。之前 APK 夹具未通过的状态不变。
