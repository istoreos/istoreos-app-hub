# 应用注册目录与包归属统一

目标：唯一生产注册目录 `/usr/share/linkease/apps.d`；独立应用运行包持有清单，LuCI-only 入口由 LuCI 包持有；app-meta 不持有清单或应用资产副本。只迁移注册目录，LinkEaseFull 自身静态资源目录不在本轮删除范围。

## 任务树和验收

1. 盘点与保护：记录两个目标仓库、实际构建映射及宿主源码的原始工作区差异；保留用户已有 FastNet 版本更新。
2. 包归属：7 个独立应用只安装新目录链接；删除 FastNet 两侧元包旧副本；DDNSTO 清单和独立图标移至 luci-app-ddnsto；OpenWrt builtin 同样注册新目录，模式不变。验收：各 ID 恰好一份登记、链接目标随所属包安装，app-meta 中无应用清单。
3. 升级与卸载：安装后精确清理自己旧链接，已知旧普通文件仅匹配原始哈希才清理；保留自定义文件；仅 rmdir 空目录。卸载只移除仍指向自己清单的注册链接。验收：执行真实 Makefile 安装配方及 postinst，覆盖全新安装、旧链接、已知旧普通清单、自定义文件、重复执行和登记替换后的卸载。
4. 宿主与文档：桌面、网关、Lua 解析器和 Docker 默认打包只使用新目录；保留 builtin 在桌面可见、网关忽略的业务边界。统一 AGENTS.md、当前开发文档和历史文件入口的指向；增加规范检查防止 app-meta 再次承载登记。
5. 构建映射：只同步本任务涉及的 services/LuCI/meta 文件，显式传播已确认的旧清单删除；先输出清单，不做全仓 rsync --delete。元包及实际改动包发布号各增加一次。
6. 自检：实际配方/升级行为、消费者测试、相关包契约、同步一致性和 git diff --check。源码迁移不等于已发布或已部署；需要下一轮 LinkEaseFull/app-entry 运行版本构建才能让宿主默认发现策略生效。
